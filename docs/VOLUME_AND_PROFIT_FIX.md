# Volume and Profit/Loss Display Fixes

## Problems Fixed

### 1. Market Volume Set to Order Quantity
**Issue**: When buying shares, the market data volume for that symbol was being set to the number of shares purchased (e.g., buying 6 shares set market volume to 6 instead of keeping it at millions).

**Root Cause**: The `update_market_after_execution()` function in the execution simulator was inserting execution prices as new market price records with the order's filled quantity as the volume. When the webapp fetched the latest price, it got this execution record with the tiny order volume.

**Fix**: Removed the `insert_execution_price()` call from `update_market_after_execution()`. Now:
- Order executions only update the market simulation state (which accumulates daily volume)
- No new price records are created with order quantities
- The regular price simulation generates proper market prices with realistic volumes

**Changed File**: `market-data-service/src/execution_simulator.rs`

```rust
async fn update_market_after_execution(...) -> Result<()> {
    if let Some(exec_price) = execution.average_price {
        // Update market simulation state (adds to daily volume)
        self.repository
            .update_market_state(symbol, exec_price, execution.filled_quantity as i64)
            .await?;

        // REMOVED: insert_execution_price() call that was creating 
        // price records with order volume
    }
    Ok(())
}
```

### 2. Holdings Show -100% Profit/Loss on New Orders
**Issue**: When buying shares, holdings immediately showed -100% profit/loss instead of starting at 0% and updating when market data refreshes.

**Root Cause**: The holdings display was using `marketDataCache[symbol]?.price || 0` for current price. When market data wasn't loaded yet, it defaulted to 0, making the calculation:
- Market Value = quantity × 0 = $0
- Total Cost = quantity × average_cost = $X
- Profit/Loss = $0 - $X = -$X
- Return % = -$X / $X × 100 = -100%

**Fix**: Changed to use the average cost as fallback when market price isn't available:
```javascript
const currentPrice = marketDataCache[holding.symbol]?.price || holding.average_cost;
```

This ensures:
- New holdings start at 0% profit/loss (price = cost)
- When market data loads, profit/loss updates to reflect actual market price
- No confusing -100% flash on new purchases

**Changed File**: `webapp/app.js`

## How It Works Now

### Order Execution Flow
1. User places order
2. API Gateway sends to Market Data Service
3. Market Data Service executes at current price
4. **Market simulation state updated** (daily volume incremented)
5. **No new price record created** (avoids volume corruption)
6. Holdings updated in User Service
7. Regular price simulation continues generating proper market prices

### Holdings Display Flow
1. User buys shares at execution price (becomes average cost)
2. Holdings display immediately:
   - Current Price = average_cost (fallback)
   - Profit/Loss = 0%
3. Market data loads in background
4. Holdings refresh with real market prices
5. Profit/Loss updates based on actual market movement

## Technical Details

### Market Simulation State
The `market_simulation_state` table tracks:
- `last_execution_price`: Last order execution price
- `last_execution_time`: When last order executed
- `daily_volume`: Cumulative daily volume (orders add to this)
- `execution_count`: Number of orders executed

This state influences price simulation but doesn't create price records.

### Price Records
The `market_prices` table stores:
- Historical price points with OHLCV data
- Generated by periodic price simulation (every 30s)
- Reflects realistic market movements
- Used by webapp to display current prices

**Separation of Concerns**:
- Orders update simulation state ✓
- Orders don't create price records ✓
- Price simulation creates price records ✓
