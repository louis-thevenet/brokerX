# ADR 001: Choix de l'architecture web et frontend

## Statut

Acceptée

## Contexte

Pour l'implémentation de l'interface web client de BrokerX, nous devions choisir une architecture appropriée. L'application doit fournir :

- Une interface d'authentification (login/registration) sécurisée avec MFA
- Un tableau de bord client avec informations de compte en temps réel
- Un système de placement d'ordres interactif
- Une consultation des données de marché en temps réel
- Une architecture extensible pour futures fonctionnalités
- Des performances élevées pour traiter les ordres en temps réel

## Décision

Nous avons choisi une **architecture de microservices avec API Gateway** et **frontend SPA (Single Page Application)** :

### Backend

- **API Gateway** (Axum) comme point d'entrée unique
- **Architecture microservices** (User, Order, Market Data services)
- **JWT + MFA** pour l'authentification
- **REST API** pour la communication frontend-backend

## Architecture implémentée

### Frontend

- **Single Page Application** (SPA) en HTML/CSS/JavaScript vanilla
- Interface avec navigation côté client
- Communication via API REST uniquement

### Backend

- **API Gateway** (Axum) comme point d'entrée unique
- **Authentification JWT + MFA** obligatoire (codes OTP par email)
- **Microservices** : User Service, Order Service, Market Data Service

## Conséquences

### Positives

1. **Séparation des responsabilités** : Frontend découplé du backend
2. **Scalabilité** : Architecture microservices avec clients optimisés
3. **Sécurité** : JWT + MFA obligatoire pour tous les utilisateurs
4. **Performance** : SPA avec cache client et requêtes asynchrones
5. **Extensibilité** : API REST documentée avec OpenAPI/Swagger
6. **Monitoring** : Intégration Prometheus pour métriques temps réel

### Négatives

2. **Latence réseau** : Dépendance aux appels API pour toutes les interactions
3. **Sécurité client** : Token JWT stocké dans localStorage (vulnérable au XSS)

### Architecture technique

- **Frontend** : `webapp/` avec index.html et app.js
- **API Gateway** : Point d'entrée avec routage vers les microservices
- **Communication** : REST API avec authentification JWT
- **Documentation** : Swagger UI pour l'API
